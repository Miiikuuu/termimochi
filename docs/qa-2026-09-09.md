# Full regression and defensive-input checks — 2026-09-09

The final runs passed. No new reproducible application crash, layout corruption
or unintended configuration overwrite was found in the covered cases. This is
evidence for the tested environment, not a guarantee for every setting or desktop.
This pass adds tests and a repeatable runner; no production behavior was changed.

## Environment

Linux x86-64; Rust 1.98.0; GTK 4.22.4; libadwaita 1.9.1; VTE 0.84.0;
Fastfetch 2.57.1. Native GUI tests used isolated Xvfb displays with the Cairo
renderer and `G_DEBUG=fatal-criticals`, at integer scales 1 and 2.

The native matrix includes font selection and Nerd Font specimens, prompt
navigation, independent scrolling and pointer input, official/imported Greeting
layouts, field editing, image conversion/background removal, source re-editing,
undo/redo, export/apply/restore, restart persistence and startup opt-in safeguards.
Existing ordinary tests cover color editing, history, input parsing, file aliases,
external-write conflicts and rejected executable/control content.

The new cross-module case combines font sizes 8/24, line/cell scales 1/2, padding
0/24, window spacing 0/32, configured grids 40/120 columns and 8/36 rows, Fit,
scrollbar/tab toggles, cursor modes, a 160-by-96 artwork, long multilingual text,

unchanged palette data and recovery to a clean, small two-line artwork.

The malformed workspace cases target ten numeric settings with negative values,
integer overflow, very large floats, null, strings, arrays and objects. Opening
them must fail without rewriting the input, changing the saved workspace or
creating a backup as a side effect.

## Reproducibility and data safety

`scripts/test-regression.py --display :91 --scale 1 --scale 2` discovers every
opt-in test, pins one compiled executable for the matrix, uses a separate process
and private D-Bus/XDG state per case, enforces timeouts and records individual
logs plus `results.json`. Use a dedicated Xvfb, never the user's active display.
The formerly reference-file-only applied-artwork test now has generated temporary
fixtures; optional external references remain read-only.

An initial runner attempt encountered a test-helper visibility compilation error
while new tests were being added. That test-only issue was corrected, the runner
was changed to pin one build, and the entire final 60-case matrix was rerun.

The real `.bashrc`, active Fastfetch configuration and saved Greeting preset had
identical SHA-256 values before and after testing. Startup/apply/restore tests
wrote temporary fixtures only. No repository commit or push was performed.

## Not established by this pass

- Native Wayland, fractional display scaling, hardware-accelerated rendering,
  other monitors/compositors and other GTK/VTE/Fastfetch versions.
- Long-duration leak/soak behavior, resource exhaustion or every possible input
  sequence; the randomized stream test is deterministic bounded coverage.
- A fresh RustSec dependency audit: `cargo-audit` was not installed locally.
  The separate CI security-audit workflow remains the place to run that check.

Xvfb emitted expected DRI3 and desktop-portal compatibility warnings. They were
not classified as application crashes; GTK criticals and test failures remained
fatal to their cases.
