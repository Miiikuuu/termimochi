# 发布候选验收卡

本轮修复：独立 Greeting 预览不跟随背景色、Greeting 切回 Full 偶发崩溃、
临时目录不在 `/tmp` 时 Starship 语言示例失败。没有改主题架构，也没有自动推送。

## 打开测试版

在项目目录运行：

```bash
bash scripts/run-isolated.sh target/qa/reachability/reproduction.termimochi-design.json
```

这是已经构建好的 Release 版。启动器会打印隔离会话目录和重开命令。
只打开、编辑测试副本，不打开日常配置；保存副本时选择该隔离目录。
隔离器不是文件访问沙箱，仍然能访问你手动选择的外部文件。

## 按顺序验收

| 操作 | 应看到什么 |
| --- | --- |
| 打开「小猫测试」副本，右上 Full → Greeting → Full | 能来回切换，不闪退；左侧切页不替换右侧场景。 |
| 同时打开两个测试主题，分别设置不同背景，改第二个的颜色 | Full 和 Greeting 都跟随各自主题，第一个窗口不染上第二个颜色。 |
| 字号改为 18，Ctrl+S，关闭后用打印的会话命令重开副本 | 仍为 18；主题名称、Kitty 目标、Prompt、GIF 保留；没有因此应用配置。 |
| 两窗口打开同一个副本，先在 A 保存，再在 B 修改并保存 | B 提示文档已在外部改变；不会覆盖 A。要重开或另存副本。 |
| 切 Fit / 100% fixed grid / Actual size，拖动编辑器滚动条，跳到输入并输入 help | 右侧与底部内容可到达；观察缩放不改主题字号/图片占位；查看历史时调色不会强制滚到底。 |
| 仅在隔离会话中 Use Theme，完成试用审阅；选择打开 Kitty | 打开的是该主题的独立会话；取消审阅不应写配置，保存不替代应用。 |
| 在隔离环境新增应用入口，更新主题后明确更新入口，再恢复 | 入口打开更新后的版本；恢复后打开旧版。仅发布新版本不应偷偷切换旧入口。日常 Kitty 图标不变。 |

应用入口的自动化已通过私有 `.desktop` → GIO → 真 Kitty 运行链验证，
不需要为了复测在日常应用菜单安装。最后两项请始终留在隔离环境中。

## 判定边界

发现闪退、跨窗口变色、保存覆盖外部修改或恢复后字节不一致，均为失败。
把截图、所用主题副本与隔离目录发来即可，不必读源码。

现有原生 Kitty 复杂 Greeting 的裁剪限制、日常 Wayland/分数缩放、
IBus 和真实用户可用性仍需单独验证，不能因为本卡其他项目通过就算通过。
完整数字、失败记录和原生截图见[测试报告](release-acceptance-2026-09-13.md)。
